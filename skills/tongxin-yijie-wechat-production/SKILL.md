# 通信伊姐公众号生产

把材料推进到用户要求的阶段，交付能审阅的实际文件或平台结果。默认口吻自然、客观、温暖、实用，面向想把AI用于工作的一般读者。作者为伊水，品牌为通信伊姐。

先读取 [账号默认](references/article-defaults.md)。跨阶段任务读取 [流程与确认](references/workflow-blueprint.md)；第三方工具、安装来源及缺失能力处理见 [依赖清单](references/skills-manifest.md)。

## 开始工作

- 有现成稿件时先读完整稿件，保留已有有效内容。
- 用户指定主题、语气、数量和阶段时按其要求执行；只补充会改变结果的关键缺失信息。
- 找新选题时核验近期来源，不把旧新闻包装成当前变化。
- 混合材料先按 [素材整理](references/source-intake.md) 归纳事实、证据与待核实点。
- 通信伊姐个人创作与其他机构的门店运营项目各自保留文件和身份。

## 1. 选题与证据

结合账号方向提出3至5个角度，说明目标读者、阅读价值和证据来源。使用 [方法层](references/methodology-stack.md) 判断话题是否有信息、好奇或共鸣。

按 [内容检查表](references/wechat-compliance-checklist.md) 做账号内容预检。该表是本账号的保守编辑约定；涉及当前平台规则时应另查官方依据，不把本地约定称为平台全面禁令。

选题确认后再围绕该角度生产正文；明确授权批量制作或自动推进时按授权范围执行。

## 2. 正文与润色

选择适合的原型：工具实践、流程拆解、行业观察、学习路径、读者问题、事件或政策解释。

围绕一个具体判断写作，用真实场景、材料和可执行动作支撑，不编造个人经历。开头简短切题，结尾使用 [账号默认](references/article-defaults.md) 的站内互动与固定尾注。

需要自然改稿时可调用已安装的 `human-writing` 或 `humanizer-zh`。咪蒙式强化只在用户明确要求时使用，保持事实与账号语气。风格切换参考 [风格模式](references/style-modes.md)。

“润色完成”须对应可见且保存的正文变化；需要写文件时检查结果文件，不把点击或任务启动算完成。正文确认后进入最终标题阶段。

## 3. 标题优选

默认调用本仓库的 `wechat-title-optimizer`。先在宿主技能目录查找；尚未独立安装时，读取同仓库相邻入口 [标题优选](../wechat-title-optimizer/SKILL.md)，不要混跑旧标题技能。

以已确认正文、目标读者和账号语气为输入，默认生成8个不同角度，事实检查后评分，给出主标题、稳妥版和传播版。用户指定数量时按其要求。

将结果留在文章目录的 `title-strategy.md`。推荐与用户确认分开记录；原标题仍有效时允许推荐保留。确认后把选定标题同步到正文元数据和后续排版、草稿投递字段。

历史表现分析可按用户要求另用 `gzh-title-strategist`；日常定题只使用标题优选的一套评分。

## 4. 封面与内文配图

身份来源为 [通信伊姐IP](references/ip-profiles/tongxin-yijie/IP_DNA.md)，同目录包含全身、三视图和八张表情参考。

默认1张2.35:1封面与1至3张16:9内文图。先规划每张图的作用，再生成和检查文字、品牌、人物一致性与裁切。证据场景优先使用真实截图。

角色出镜优先调用已安装的 `gimi-illustration`，传入 `$IP=tongxin-yijie`、对应风格与画幅，并按其规则完成风格校准。若其内置IP资源缺失，使用本包参考图与DNA；不要假称新机器已经具备旧机器的校准资产。

纯概念图可用可用的图像工具或解释图技能。实际输出尺寸取决于当前工具；用支持的画幅生成后等比裁切到目标比例，不拉伸，不把旧工具尺寸限制写成永久事实。

缺少图像能力时保留配图计划并说明该阶段尚未生成。配图经检查与风格确认后才进入排版。

## 5. 微信排版

普通排版使用已安装的 `baoyu-markdown-to-html`，默认 `default` 主题、蓝色、16px正文；用户设置优先。已配置可用的旧排版工具也可沿用，缺失时不调用不存在的入口。

用户说“精排”“高级排版”时使用 `gzh-design` 的主题组件，应用账号16px正文与20px章节标题，并执行其HTML校验。保持第三方组件在外部工具中，不复制到本仓库。

保留Markdown作为内容源、最终HTML作为草稿投递源，并提供可见预览。检查首屏、标题层级、图片、摘要、结尾和微信兼容性。预览确认后才向平台投递。

## 6. 草稿投递与核验

先读取 [投递默认](references/publishing-defaults.md)。用户要求制作文章或排版不自动授权平台投递；已有“保存草稿箱”授权时执行，不重复征询。

默认用 `baoyu-post-to-wechat` 的API草稿路径，输入最终HTML、选定标题、伊水、摘要和封面。凭据只在本机配置。API无法投递且已授权草稿操作时，可使用已登录浏览器，报告实际路径。

成功后检查平台返回标识、草稿列表与内容，确认标题、作者、封面和内图。核验不到就报告“尚未核验”，不要把HTTP响应、点击或本地预览算作草稿保存。

正式发布仅在用户明确要求且稿件审核完成时进行，并以平台发布状态或文章链接证明。GitHub发布本技能包不代表授权发布公众号文章。

## 7. 复盘与交付

按 [复盘](references/post-publish-review.md) 记录实际标题、素材、图片、排版源和投递路径。比较同账号与相近内容，区分标题因素、选题因素和分发因素。

交付时说明已经到达的阶段、文件、平台标识与剩余条件。状态使用“本地稿件 / 预览 / 草稿箱已保存 / 已正式发布”等明确措辞。

article-folder/
├── source-notes.md

├── images/

├── preview.html

如已有工具生成的目录结构，沿用即可。上游内容修改时撤销受影响的下游确认并保留旧产物，不把确认从旧稿沿用到新稿。
