# 流程与确认

正常顺序为：选题与证据 → 正文 → 标题 → 配图 → 排版 → 草稿投递 → 正式发布或复盘。

## 五个制作确认点

| 确认点 | 审核产物 | 确认意味着 |
|---|---|---|
| 选题 | 角度、读者、证据、待核实点 | 可以围绕选定角度写稿 |
| 正文 | article.md及摘要 | 可以以此正文拟定最终标题 |
| 标题 | 8个候选、评分与选定标题 | 后续排版和草稿字段使用选定标题 |
| 配图 | 封面与内图及风格检查 | 这些图片可进入排版 |
| 排版 | 最终HTML与可见预览 | 该版本可在已授权范围内投递草稿 |

用户已明确确认的内容不重复追问。用户授权批量或自动推进时按既有授权执行，不强制重复每一确认；没有授权时不替用户把候选或预览标记为已确认。

确认须对应具体版本。选题或正文修改时撤销受影响的标题、配图、排版确认；只改标题也要重查封面标题与HTML元数据。保留旧产物供比较。

## 阶段验收

- 正文生成或润色：结果文本可见，必要时已保存，内容变化可检查。
- 标题生成：读取 `wechat-title-optimizer`，给出真实不同的候选与可解释评分；选定标题与用户确认分开。
- 图像：确有图片文件，技术检查与风格审核分别完成。
- 排版：最终HTML有效，预览对应同一稿件；精排须用 `gzh-design`。
- 草稿：平台保存标识、草稿列表与内容可核验。
- 正式发布：平台发布状态或可访问文章链接可核验。

## 缺少能力

先完成仍可执行的部分，并说清未完成阶段与缺少的依赖。标题技能随包提供；生图、排版、微信开发权限与登录状态不能由文件包替代。

## 记录方式

每篇文章在 `publish-report.md` 留下已确认阶段、源文件和实际结果。敏感凭据不写入报告；对外分享前移除私有草稿标识和非公开材料。

标题方案存入 `title-strategy.md`。日常生成只用合并版的一套评分，避免把多个标题Skill的数量和规则混在一起。
